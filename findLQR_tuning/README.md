# findLQR_tuning

Workbench and regression fixtures for tuning `amplican::findLQR()` — the
unsupervised off-target / low-quality-read filter that misfires at high CRISPR
editing rates.

## The problem

`findLQR()` (`R/helpers_filters.R`) is an **unsupervised** filter: for each amplicon ID it
clusters reads on two per-read features — alignment `score` and event density
(`events / max(end)`) — using CLARA. It tries k=2 vs k=3; if k=3 has the better
silhouette it deletes the cluster farthest from "good reads" (high score / few
events). It was designed to remove off-target / misaligned junk.

At **high editing rates (~90%)** the edited reads *are* the high-event /
lower-score population, so `findLQR` mistakes the mutant majority for junk and
deletes it. In the synthetic benchmark this collapses `Reads_Filtered` by ~62%
and drops an apparent 90% editing rate to ~76% (CRISPResso2 and CRISPECTOR2,
which don't do unsupervised read-removal, stay at ~90%). It fires for 17/20
guides per panel and across **all** indel-size panels at 90% — i.e. it is driven
by editing *fraction*, not indel size. Below ~66% editing it (correctly) never
fires.

Three structural traits of the rule cause this:

1. **Geometry-only**: the culled cluster is chosen purely by distance from the
   "good" corner, with **no size guard** — so the majority edited cluster is fair
   game.
2. **Unsupervised**: it ignores amplican's matched WT controls that could define
   the legitimate score floor.
3. **Conflates "many events" with "low quality"**: genuine editing raises the
   event count; true junk is low-score from *mismatches*, not indels.

There is also a complement false-negative: under high editing with clean cluster
separation `findLQR` culls *nothing*, missing genuine junk (case 08).

## Folder layout

```
findLQR_tuning/
  README.md              this file
  capture_fixtures.R     rebuilds the fixtures from the benchmark raw_events
  reproduce_bug.R        minimal demo: case 01 culls ~62% of EDITED reads
  explore_clara.R        workbench: feature-space plot + k2/k3 decision per case
  fixtures/<case>/
    events.csv           the EXACT data.frame findLQR receives (hermetic)
    expected.json        intent: description, current behaviour, desired behaviour
  plots/                 generated by explore_clara.R
```

## The 8 cases

Faithfulness: `capture_fixtures.R` re-applies `findEOP()` + `findPD()` to the
benchmark `raw_events.csv` — exactly the two filters that precede `findLQR()` in
`amplicanPipeline()` — and **asserts** the reconstructed `Low_Score` equals the
pipeline's reported value before shipping a fixture. (All six real cases match
the pipeline exactly.)

| Case | Source | Editing | Today findLQR | Desired |
|------|--------|--------:|--------------|---------|
| `01_high_edit_falsepos` | real (nlgn4a, 1freq) | 90% | **culls 1866** | filter ~0 (THE BUG) |
| `02_high_edit_escapee`  | real (cnsta, 1freq)  | 90% | culls 0 | 0 (borderline escapee) |
| `03_mid_edit_negative`  | real (nlgn4a, 1freq) | 66.7% | culls 0 | 0 (guard) |
| `04_low_edit_negative`  | real (nlgn4a, 1freq) | 33.3% | culls 0 | 0 (guard) |
| `05_pure_wt`            | real (nlgn4a, 1freq) | 0% | culls 0 | 0 (guard) |
| `06_genuine_junk`       | synthetic (WT maj + junk) | low | **culls 120 junk** | keep firing |
| `07_large_del_high_edit`| real (nlgn4a, 4freq) | 90% | **culls 1890** | filter ~0 (bug, large del) |
| `08_synthetic_boundary` | synthetic (edited maj + junk) | high | culls 0 (misses junk) | cull junk only |

The two **load-bearing** cases for any fix: **01 must stop firing** and **06 must
keep firing**. 02–05 are regression guards; 07 shows the bug is editing-fraction
driven; 08 is the false-negative complement.

## Usage

```bash
cd /home/ai/current/amplican

# 1. (re)build fixtures from the benchmark — verifies fidelity vs pipeline
Rscript findLQR_tuning/capture_fixtures.R

# 2. see the bug on a single case
Rscript findLQR_tuning/reproduce_bug.R

# 3. inspect any case's feature space + clara decision (writes plots/)
Rscript findLQR_tuning/explore_clara.R 01_high_edit_falsepos
Rscript findLQR_tuning/explore_clara.R                    # all 8
```

All three scripts `pkgload::load_all()` the package source, so they exercise the
**current** `findLQR` — re-run them after every edit to the function.

## Promoting to package tests

The real-data fixtures are byte-exact `findLQR` inputs, so a subset can be copied
into `inst/extdata/findLQR/` and asserted on by a new `tests/testthat/test_findLQR.R`,
encoding each case's `desired` behaviour as the regression target while the fix
is developed.
